# QA Checklist

## Перед каждым демо
- [ ] публичная форма заявки открывается
- [ ] заявка создаётся и появляется в CRM
- [ ] Telegram уведомление приходит
- [ ] все роли входят без ошибок
- [ ] demo-данные на месте
- [ ] `.env` содержит явные demo-логины для `creator / owner / manager / detailer`

## После изменений в коде
- [ ] `npm run build` проходит без ошибок
- [ ] публичный flow работает end-to-end
- [ ] rate limiting срабатывает (`429` на 4-й запрос)
- [ ] валидация работает (`400` на плохой payload)
- [ ] RLS: manager не видит данные другого tenant (когда будет multi-tenant)
- [ ] creator `/platform` открывается и показывает cross-company overview
- [ ] creator `QA pass` режим показывает проблемные компании без white-screen
- [ ] creator `Handoff` режим показывает стадии `без подписки / мимо тарифа / company inactive / не закрыта`
- [ ] компания из handoff открывается в creator card с activation checklist

## Роли и доступы
- [ ] owner видит всё
- [ ] manager видит свои рабочие разделы без лишних настроек
- [ ] technician видит только назначенные задачи
- [ ] смена роли работает корректно
- [ ] creator остаётся только в `/platform`
- [ ] owner не попадает в `/platform`

## UI / визуал
- [ ] интерфейс открывается на мобильном
- [ ] нет явных UI-багов на главных экранах
- [ ] статусы заявок отображаются правильно
- [ ] кнопки и формы читаемы на светлом фоне
- [ ] в creator у активных / paused / archived компаний цвета не сливаются
- [ ] QA / handoff / attention блоки читаются как разные слои

## Автоматизации
- [ ] `lead-alert` работает
- [ ] `follow-up-reminder` работает
- [ ] `daily-digest` работает
- [ ] `public-request` обрабатывает корректные заявки

## Клиентский сценарий
- [ ] новая заявка с сайта доходит до CRM
- [ ] менеджер может открыть заявку и добавить заметку
- [ ] follow-up сохраняется
- [ ] история клиента отображается корректно

## Multi-company QA pass
- [ ] вторая компания не видит чужих клиентов / лидов / услуг
- [ ] `/request?company_slug=...` создаёт заявку именно в нужную компанию
- [ ] `/status/:token` продолжает открываться после company-aware изменений
- [ ] active / paused / archived компании ведут себя корректно в creator и public flow
- [ ] active company без подписки / owner / services сразу видна в `QA pass`
