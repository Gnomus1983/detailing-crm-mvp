# Competitor Gap Plan

Основа анализа: сравнение идей из Salesforce, HubSpot, Pipedrive, Bitrix24, amoCRM/Kommo, Odoo, AutoLeap, Shop-Ware, Tekmetric, Shopmonkey, RemOnline и похожих CRM для сервиса.

Главный вывод: не копировать универсальные CRM целиком. Для Detail CRM сильнее ниша автодетейлинга: директор видит деньги и контроль, мастер видит простые задачи, клиент видит статус машины и фото.

## Что уже можно считать сильной базой

- CRM уже не универсальная, а направлена на детейлинг/автосервис.
- Есть роли: директор, менеджер, мастер.
- Есть публичная заявка без входа.
- Есть клиентская статусная ссылка без логина.
- Есть фото до/после.
- Есть Telegram-уведомления менеджеру.
- Есть первый контур Telegram-уведомления клиенту.
- Есть базовая касса директора.
- Есть PWA-основа.

## Ближайшие действия

1. Зафиксировать live MVP: полный прогон `/request -> CRM -> готово -> Telegram -> /status/:token`.
2. Доработать карточку автомобиля как отдельную сущность, а не просто поля в заявке.
3. Добавить чеклист мастера внутри заявки.
4. Добавить согласование клиентом допработ на `/status/:token`.
5. Довести оплату: предоплата, остаток, способ оплаты, долг.
6. Усилить отчеты директора: загрузка мастеров, просроченные заявки, неоплаченные работы.
7. После этого вернуться к PWA: сделать клиентскую страницу более похожей на установленное приложение.

## Что пока не делать

- Не строить полный Salesforce/Bitrix.
- Не делать сложный омниканал до стабильного Telegram.
- Не делать склад и маржинальность до первой продаваемой версии.
- Не делать AI до завершения базового бизнес-потока.
- Не делать полноценный клиентский кабинет с логином, пока ссылка `/status/:token` закрывает первую продажу.

### 1. Bitrix24 для автосервиса

Их рабочая цепочка:

`Запись -> приемка -> планирование -> запчасти -> работа -> контроль качества -> закрытие заказ-наряда -> аналитика`

Что у них сильное:
- все обращения из звонков, сайта, мессенджеров и онлайн-записи попадают в CRM;
- в карточке заказа виден статус ремонта, история клиента, автомобиль, комментарии мастеров и документы;
- онлайн-запись учитывает услугу, время и специалиста;
- расписание учитывает загрузку мастеров, боксов и оборудования;
- процесс идет по сценарию: прием, диагностика, согласование, ожидание запчастей, ремонт, выдача;
- система сама ставит задачи, чек-листы, двигает заказ по этапам;
- есть склад, остатки, стоимость материалов;
- клиент получает статусы и напоминания;
- директор видит продажи, деньги, KPI и прогноз загрузки.

Вывод для нас:
- не копировать весь Bitrix24;
- взять автосервисную цепочку как основу;
- ближайшие наши пробелы: приемка, чеклист мастера, согласование допработ, календарь загрузки, контроль качества.

### 2. QuoteIQ / mobile detailing логика

Сильная логика QuoteIQ:
- клиент сам выбирает услуги и видит цену в реальном времени;
- клиент может сам записаться в свободный слот;
- фото и видео привязаны к работе и клиентской истории;
- before/after используется не только для отчета, но и для продажи;
- есть job costing: цена минус работа мастера минус материалы = реальная прибыль;
- есть review request после оплаты;
- есть route optimization для мобильных бригад;
- есть employee hub: GPS, время, роли, команды.

Вывод для нас:
- наша `/request` форма уже похожа на self-quote, но цены должны быть железно правильными;
- надо добавить допуслуги и итоговую цену до отправки;
- фото до/после уже есть, но надо сделать из них “доказательство работы”;
- следующая взрослая финансовая функция: прибыль по заявке, а не только выручка.

### 3. AutoLeap / Tekmetric / Shop management

Сильная логика:
- digital vehicle inspection: мастер фиксирует состояние машины фото/видео/чеклистом;
- estimate building: из осмотра быстро собирается предложение клиенту;
- customer approval: клиент утверждает работы;
- technician app: мастер работает с телефона;
- work board: директор видит весь цех по статусам;
- customer communication: клиент всегда понимает, что происходит;
- inventory + parts/labor: система считает материалы, работу и маржу;
- reporting: директор видит деньги, эффективность мастеров, загрузку, услуги.

Вывод для нас:
- нам нужна не просто “заявка”, а “карточка работы по машине”;
- мастерская логика должна стать такой:
  `Принял -> Осмотр -> Фото -> Работы -> Согласование -> Выполнение -> Контроль -> Готово -> Оплата`;
- клиентская ссылка должна стать мини-приложением доверия:
  статус, фото, цена, согласовать, связаться.

## Приоритетный план после анализа конкурентов

### Этап A: Закрыть текущий MVP

1. Полный live-прогон:
   `/request -> CRM -> назначить мастера -> статус В работе -> фото -> статус Готово -> Telegram клиенту -> /status/:token`.
2. Убедиться, что цена услуги везде одинаковая:
   форма, карточка заявки, Telegram, касса директора.
3. Убедиться, что мастер не видит финансы директора и не ловит белый экран.

### Этап B: Сделать автосервисную основу

1. Отдельная карточка автомобиля:
   марка, модель, год, номер, история работ, фото, комментарии, дефекты.
2. Приемка автомобиля:
   состояние кузова, салона, повреждения, фото до, комментарий клиента.
3. Чеклист мастера:
   принял, помыл, полировка, керамика, контроль, готово.
4. Контроль качества:
   директор/менеджер подтверждает, что машину можно выдавать.

### Этап C: Клиентское доверие

1. На `/status/:token` добавить блок согласования:
   допработа, цена, кнопка “Одобрить”.
2. Добавить вопрос клиенту:
   “Есть вопрос по работе?” -> Telegram/WhatsApp/форма.
3. После готовности:
   сообщение клиенту + ссылка + просьба оставить отзыв.

### Этап D: Деньги

1. Предоплата.
2. Остаток.
3. Способ оплаты: наличные, карта, перевод.
4. Долги.
5. Прибыль по заявке:
   `сумма клиента - материалы - работа мастера`.
6. Отчет директора:
   день, неделя, месяц, год, мастера, услуги, долги, средний чек.

### Этап E: Позже

1. Склад химии и материалов.
2. Расписание боксов и мастеров.
3. Маршруты для мобильного детейлинга.
4. Google reviews / отзывы после готовности.
5. AI-помощник.
6. Полный клиентский кабинет.
