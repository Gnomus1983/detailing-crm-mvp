# Marketing Site Plan

Цель: сделать отдельный продающий сайт-витрину для владельцев детейлинг-центров, автомоек и шиномонтажей, чтобы продукт можно было не только показать в CRM, но и нормально продавать.

## 1. Роль сайта-витрины

У продукта должно быть 3 входа:

1. `Сайт-витрина`
   - объясняет продукт
   - показывает выгоду
   - продает подписку
   - собирает заявки на демо

2. `CRM`
   - вход для директора, менеджера, мастера

3. `Клиентский контур`
   - публичная запись
   - страница статуса машины

## 2. Кому сайт продает

Основная аудитория:

- владельцы детейлинг-центров
- владельцы автомоек
- владельцы шиномонтажей
- небольшие руководители автоуслуг

Сайт не должен говорить на языке программистов.
Он должен говорить на языке бизнеса:

- меньше хаоса
- больше контроля
- виден статус каждой машины
- менеджер не теряет заявки
- директор видит деньги
- клиент видит прогресс без звонков

## 3. Что должен делать сайт

Сайт должен:

- объяснить, что это за продукт
- показать, для кого он
- показать реальные сценарии работы
- показать тарифы
- дать заявку на демо
- дать переход в CRM

## 4. Рекомендуемая структура

### Главная страница `/`

Блоки:

1. Hero
   - сильный оффер
   - короткий подзаголовок
   - две кнопки:
     - `Запросить демо`
     - `Посмотреть как работает`

2. Для кого
   - детейлинг
   - автомойка
   - шиномонтаж

3. Что решает
   - заявки
   - мастера
   - статус машины
   - оплаты
   - контроль директора

4. Как работает
   - клиент оставляет заявку
   - менеджер принимает
   - мастер ведет работу
   - клиент видит статус
   - директор видит деньги

5. Роли
   - директор
   - менеджер
   - мастер
   - клиент

6. Скриншоты интерфейса
   - CRM
   - заявка
   - статус клиента
   - мобильный вид

7. Тарифы
   - Start
   - Pro
   - Studio

8. FAQ
   - сколько стоит
   - нужен ли App Store
   - можно ли подключить Telegram
   - можно ли использовать для автомойки / шиномонтажа

9. Final CTA
   - форма заявки на демонстрацию

### Страница возможностей `/features`

Блоки:

- заявки и запись
- работа менеджера
- кабинет мастера
- клиентская страница статуса
- Telegram-уведомления
- оплаты и касса
- отчеты директора

### Страница тарифов `/pricing`

Структура:

- сравнение пакетов
- что входит
- лимиты по сотрудникам
- лимиты по компаниям не нужны, так как SaaS = одна компания на клиента
- CTA на демо

### Страница демо `/demo`

Что показывать:

- краткое описание demo-flow
- кнопка входа в CRM
- кнопка на публичную форму
- кнопка на клиентский статус

### Страница входа `/login`

Отдельно:

- вход сотрудников
- ссылка на сайт-витрину обратно

## 5. Какой смысловой оффер использовать

Не писать просто:

- `CRM для автосервиса`

Лучше писать в терминах результата:

- `Контроль заявок, мастеров и оплат в одном месте`
- `Клиент видит статус машины без звонков`
- `Директор видит загрузку, кассу и работу команды`

## 6. Что особенно важно показать

Сильнейшие продуктовые блоки для продажи:

- клиент видит статус машины в реальном времени
- фото до/после
- мастер работает по простой карточке
- директор видит деньги и загрузку
- запись приходит сразу в систему

Это сильнее продает продукт, чем просто список таблиц и сущностей.

## 7. Как связать витрину с будущим SaaS

Сайт должен продавать не “разработку под вас”, а именно продукт по подписке.

То есть на витрине нужно заложить:

- тарифы
- кнопка `Запросить демо`
- кнопка `Подключить центр`
- блок `Для детейлинга / автомойки / шиномонтажа`

Это подготовит правильное позиционирование под many-company SaaS.

## 8. Что делать в дизайне

Витрина должна быть визуально сильнее, чем CRM:

- современная типографика
- качественные скриншоты
- чистая сетка
- автомобильная атмосфера без дешевой “неоновой” стилистики
- акцент на премиальность и управляемость

Сайт должен выглядеть как продукт, за который платят подписку.

## 9. Что не делать

- не делать огромный корпоративный сайт на 20 страниц
- не писать “мы предлагаем инновационные решения”
- не показывать только абстрактные иконки без реальных экранов
- не превращать сайт в техническую документацию

## 10. Ближайший порядок реализации

1. Зафиксировать структуру сайта
2. Подготовить тексты и офферы
3. Подготовить тарифную таблицу
4. Подготовить реальные скриншоты продукта
5. Собрать маркетинговый frontend
6. Связать его с CRM и публичным demo-flow

## 11. Главный результат

После запуска сайта-витрины у тебя будет не просто CRM, а полноценный SaaS-контур:

- есть что продавать
- есть куда вести трафик
- есть где показывать тарифы
- есть где собирать заявки владельцев центров
- есть как масштабировать продукт на многие компании
